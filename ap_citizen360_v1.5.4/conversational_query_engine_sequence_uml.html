Conversational Query Engine — End-to-End Sequential Architecture

AP Citizen 360 v1.5.4 · LangGraph Multi-Agent Orchestration · 2-Tier Valkey Cache · Hybrid MCP RAG

Sequence Workflow: User → Valkey Queue → 2-Tier Cache → LangGraph → MCP Tools → Impala DB
100%
01
Ingestion & Speech-to-Text

Accepts user queries via HTTP REST (POST /ask), WebSocket (/ws), or raw voice audio. Audio streams are transcribed in real-time using local Faster-Whisper models.

FastAPI Faster-Whisper WebSocket /ws
02
FIFO Queue & Worker Concurrency

Queries are non-blocking enqueued into Valkey FIFO queue (valkey:query_queue). Concurrent worker pools dequeue jobs in strict arrival order to prevent Ollama GPU/CPU thrashing.

Valkey Queue Worker Pool Async Concurrency
03
2-Tier Hybrid Cache Resolution

valkey_cache_check_node executes Tier-1 SHA256 exact-match hash lookup. On miss, Tier-2 evaluates semantic vector cosine similarity (≥ 0.97) in milvus_cache.db. Instant SQL reuse on Hit.

Tier-1 Hash Tier-2 Milvus Lite LRU 300
04
Intent & Entity Classification

intent_node parses user question with LLM to extract intent label, temporal filters (years), geographical entities (districts, mandals), and target department scope (ap_citizen360).

LangGraph Ollama LLM Entity Extraction
05
Exact Few-Shot Fast Path

deterministic_search_node searches few_shot_store. If semantic match score ≥ 0.99, eval_fast_path_node directly binds gold SQL parameters and executes without LLM generation overhead.

Fast Path few_shot_store ≥ 0.99 Match
06
MCP Semantic Schema Retrieval

On dynamic queries, initialize_node calls MCP tool retrive_schema_rag to fetch table DDLs, column definitions, distinct values, and NL→SQL pairs from Milvus vector index.

MCP Tool schema_store Distinct Values
07
Self-Directed SQL Generation

llm_node receives schema context and domain guidelines. Constructs syntactically correct, partition-optimized Impala/Hive/SQLite SQL with tool invocation execute_sql.

Ollama Qwen2.5 Tool Call Impala Syntax
08
Sandboxed SQL Execution

MCP SQL Server (mcp_hive_execution.py / mcp_sql_execution.py) executes queries against Impala CDP cluster (Kerberos GSSAPI) or local SQLite with SELECT-only safety enforcement.

Impala Iceberg Kerberos SASL Read-Only
09
Self-Correction & Verification

verify_node inspects query output. On SQL runtime errors, feeds error traceback into a targeted RAG re-retrieval and self-repair loop (up to 3 retries). On success, caches to Valkey.

Self-Healing 3x Retries Auto-Cache
10
Unstructured Document RAG

For policy guidelines, circulars, and schemes, doc_search_node invokes search_documents across vectorized PDF/DOCX passages in Milvus and synthesizes comprehensive answers.

document_store PDF / DOCX RAG Citation Synth
11
Summarization & Chart Synthesis

summarization_node transforms tabular SQL result sets into natural executive insights, markdown data tables, and automatic Chart.js / Mermaid visual chart metadata for frontend graphs.

Executive Summary Chart Spec Markdown Table
12
Live Delivery & Audit Logging

Payload streams back to client via SSE / WebSocket. Session is saved to SQLite chat_history.db and audit metadata written to thread-safe query_log.xlsx.

SSE Stream chat_history.db query_log.xlsx
